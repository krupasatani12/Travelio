- **Budget estimate**: Quick budget widget for this place
- **Safety score**: Safety indicator for the city
- **Related places**: Other places in the same city

## Phase 4: AI-Powered Trip Planner Overhaul

**Goal**: Full AI chatbot integration in trip planning, city/place selection with checkboxes, day-wise planning, AI time management overview, and auto email.

### Frontend

#### [MODIFY] [TripPlanner.jsx](file:///d:/Travel.IO/client/src/pages/TripPlanner.jsx)
- **Step 1**: Form (existing) — categories, vibes, budget, days, group size, month
- **Step 2**: AI Suggestions — city cards from recommendations
- **Step 3** (NEW): **City & Place Selection**
  - User selects a city card
  - Checkboxes appear for places within that city
  - If multi-day trip, user assigns places to specific days
  - "Add Another City" button for multi-city trips
- **Step 4** (NEW): **AI Chatbot Suggestion Panel**
  - Send all form data + selected places to Mistral AI
  - AI returns a full day-wise itinerary with time management (like the Somnath→Dwarka example)
  - Display the AI overview in a rich formatted panel
  - **Extended plan section**: "If you extend by 1 day and ₹X more budget, you could also visit..."
- **Step 5** (NEW): **Final Overview & Confirm**
  - Summary of all days, places, budget, safety
  - Each suggestion card is clickable → shows place details with budget & safety
  - **Auto-email**: On "Confirm Trip", send the full AI itinerary email with:
    - Day-wise plan
    - Place cards with Google Maps location links
    - Per-day "Route Map Link" (Google Maps directions for that day's route)
    - Budget breakdown
    - Safety tips
- **Login gate**: After filling the form (Step 1), if user is not logged in, freeze all inputs and prompt login

### Backend

#### [MODIFY] [chatbot.routes.js](file:///d:/Travel.IO/server/routes/chatbot.routes.js)
- Add `POST /api/chatbot/trip-plan` → sends trip details to Mistral AI, returns structured itinerary
- The prompt instructs Mistral to return a JSON-structured day-wise plan with times, places, costs, tips

#### [MODIFY] [trip.routes.js](file:///d:/Travel.IO/server/routes/trip.routes.js)
- Add `POST /api/trips/confirm-full` → saves full trip + triggers email with AI overview
- Add `POST /api/trips/extend-suggestion` → AI suggests what to add with more days/budget

#### [MODIFY] [emailService.js](file:///d:/Travel.IO/server/services/emailService.js)
- Add `sendTripPlanEmail(to, tripPlan)` → rich HTML email with:
  - Full AI itinerary (day-wise)
  - Place cards with images and Google anchor links
  - Per-day Google Maps direction links
  - Budget and safety summary

### Frontend — Tool Settings (Profile)

#### [MODIFY] [Dashboard.jsx](file:///d:/Travel.IO/client/src/pages/Dashboard.jsx)

## Phase 5: Credit System

**Goal**: Per-user daily credit limits for AI features.

### Database

#### [MODIFY] [User.js](file:///d:/Travel.IO/server/models/User.js)
- Add fields:
  - `credits`: `{ daily: Number (default 100), used: Number (default 0), lastReset: Date }`
  - `creditHistory`: Array of `{ action: String, cost: Number, timestamp: Date }`

### Backend

#### [NEW] `server/middleware/creditCheck.js`
- Middleware that checks if user has enough credits before AI operations
- Auto-resets credits at midnight IST daily
- Credit costs:
  - Chat message: 2-5 credits (based on response length)
  - Trip planner full suggestion: 10 credits
  - Landmark detection: 3 credits

#### [MODIFY] [chatbot.routes.js](file:///d:/Travel.IO/server/routes/chatbot.routes.js)
- Apply `creditCheck` middleware to chat endpoints
- Deduct credits after successful response

#### [MODIFY] [auth.routes.js](file:///d:/Travel.IO/server/routes/auth.routes.js)
- `GET /api/auth/me` → now includes credit status in response

### Frontend

#### [MODIFY] [Dashboard.jsx](file:///d:/Travel.IO/client/src/pages/Dashboard.jsx)
- Show credit usage bar: "42/100 credits used today"
- Credit history log

#### [MODIFY] [ChatbotPage.jsx](file:///d:/Travel.IO/client/src/pages/ChatbotPage.jsx)
- Show remaining credits in chat header
- Disable chat input when credits exhausted

## Phase 7: Admin Dashboard Overhaul

**Goal**: Python charts, API settings, online/offline mode, credit management.

### Backend — Django ML Service

#### [NEW] `ml-service/api/charts.py`
- Endpoints that generate Matplotlib/Seaborn chart images:
  1. `GET /api/charts/ml-performance` → ML model confidence line chart
  2. `GET /api/charts/safety-heatmap` → Safety scores heatmap by state
  3. `GET /api/charts/budget-duration` → Budget vs duration scatter plot
  4. `GET /api/charts/vibe-distribution` → Donut chart of searched categories
  5. `GET /api/charts/api-usage` → API request area chart

### Backend — Node.js Admin API

#### [MODIFY] [admin.routes.js](file:///d:/Travel.IO/server/routes/admin.routes.js)
- Add endpoints:
  - `GET /api/admin/stats` → enhanced stats (users, journals, trips, credits used, emails sent)
  - `PUT /api/admin/settings` → update system settings (online/offline mode, LLM params)
  - `PUT /api/admin/credits/:userId` → admin can modify user credit limits
  - `GET /api/admin/credit-usage` → aggregate credit usage data for charts
  - `GET /api/admin/email-logs` → email delivery status logs

#### [NEW] `server/models/SystemSettings.js`
- Singleton document storing:
  - `mode`: 'online' | 'offline'
  - `llm`: `{ temperature, maxTokens, topP }`
  - `apiLimits`: `{ defaultCreditsPerDay, maxCreditsPerDay }`
  - `features`: `{ chatbotEnabled, emailEnabled, budgetToolEnabled, safetyToolEnabled }`

### Frontend

#### [MODIFY] [AdminDashboard.jsx](file:///d:/Travel.IO/client/src/pages/AdminDashboard.jsx)
- **Stats section**: Enhanced stat cards (users, journals, trips, total credits consumed, emails sent)
- **Charts section**: 5 chart panels loading images from Django ML service
- **API Settings panel**:
  - Temperature slider (0.0-1.0)
  - Max Tokens input
  - Top-P slider
- **Online/Offline toggle**: When offline → chatbot disabled, email disabled, AI features disabled
- **Credit Management**: Table of users with their credit usage, admin can adjust limits
- **Quick Actions**: Wire existing buttons to real endpoints (ML retrain, cache clear, emergency stop)
